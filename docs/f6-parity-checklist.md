## Findings

- **Row 4 — was the one parity criterion not met at F6 close; closed at F7.1.** Connection-name string-literal autocomplete (`Connections.sql "…"`) regressed when `src/FSharpQueryStudio.Ui/ConnectionNameCompletion.fs` was deleted in F6.2. F6's spec forbade extension feature work, so it was recorded here and moved to the F7 backlog. **F7.1 (2026-09-07)** reimplemented it in `editors/vscode/src/lang/connection-name-completion.ts` — a dedicated completion provider, the Avalonia regex ported verbatim, names from `connections.api.list()`. See the DEVLOG entry `2026-09-07 — F7.1`. All eight F6 criteria are now met.
- **Row 6 — one spec assertion fails on Windows only, green in CI.** `connections.test.ts` "resolves a `{password}` token from SecretStorage over the reverse channel" fails its *final* assertion locally on Windows: `message.includes(sentinel)`. The test's own comments label this "KNOWN NPGSQL VARIANCE" — some Npgsql builds report `"No such host is known."` without echoing the resolved host. The **guaranteed** bridge proof earlier in the same test (`!message.includes("{password}")` — the literal token was substituted by a value fetched over `secret/get`) passes locally, so the reverse secret bridge is proven to run. The full spec runs green in `.github/workflows/vscode-extension.yml` (Linux, `xvfb-run`), which fires on every push to `main-vscode` and is the stated merge gate. Not a parity gap.
- **Row 8 — the original design's second OutputChannel is not built on `main-vscode`.** The migration design envisaged both a `"F# Query Studio"` and a `"F# Query Studio (Worker)"` channel (and an `src/log/channel.ts` module); on `main-vscode` only the single `"F# Query Studio"` channel exists, created inline in `src/extension.ts`. The parity criterion (in-app log viewer downgraded to an OutputChannel + the worker's Serilog file sink, no in-app viewer) still holds — the Row 8 Evidence cell above records only what is present. The missing second channel is ruled F7 backlog, not an F6 parity gap.
- **Not a checklist row, but observed — fixed at F7.7 (2026-09-07).** `intelligence.test.ts` "reports a diagnostic for a broken edit" failed locally (no diagnostic within the 30 s poll). Root cause: `FsacBridge.fsacUriFor` did not strip `#`/`%` from a `vscode-notebook-cell:` URI, so the synthetic `file://` URI handed to FSAC carried a literal `#` fragment that truncated away the `.fsx` extension — FSAC never script-analysed the cell, so `analysis/check` always timed out to `[]`. Fixed by sanitising the synthetic filename to `[A-Za-z0-9._-]` and guaranteeing a `.fsx` suffix. The broken-edit spec now passes in < 1 s; local `test:vscode` is 12 passing / 1 failing (only Row 6's documented Windows/Npgsql `{password}` variance remains). See DEVLOG `2026-09-07 — F7.7` and `docs/tasks/f7-7-fsac-notebook-cell-uri-diagnostics.md`. A separate pre-existing ~40 %/run flake in the full `FSharpQueryStudio.Fsac.Tests` suite (a `documentAnalyzed`-before-`publishDiagnostics` ordering assumption) is documented there as an F7 follow-up.
